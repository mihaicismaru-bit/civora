# CIVORA v1.0 Release Checklist

This checklist is the canonical release-closure gate. It does not authorize merge, tag or release by itself.

## Technical gates

- [x] Durable persistence/recovery architecture implemented.
- [x] Cross-process locking implemented.
- [x] Windows-native runtime validation established.
- [x] Transaction/dead-letter audit implemented.
- [x] Fact Kernel and claim/evidence reconciliation implemented.
- [x] Contradiction/conflict gate implemented.
- [x] Editorial approval state machine implemented.
- [x] Restart-safe approved re-entry implemented.
- [x] Authorized-fact-only Story Engine input implemented.
- [x] Evidence-constrained reader-visible rendering implemented.
- [x] Unified health/remediation implemented.
- [x] Operator remediation runbook implemented.
- [ ] Expanded release CI green on the proposed RC head.
- [ ] Python 3.10 lower-bound job green.
- [ ] Python 3.11/3.12/3.13 Linux jobs green.
- [ ] Windows-native job green.
- [ ] Built sdist/wheel job green.
- [ ] Clean wheel install and installed CLI smoke green.
- [ ] Deterministic `tools/release_preflight.py` green.

## Release metadata gates

- [x] README reflects current release-closure baseline.
- [x] Historical import provenance is clearly labeled.
- [x] Changelog created with an Unreleased section.
- [x] Version synchronization regression contract exists.
- [ ] Final package version set to `1.0.0` in `pyproject.toml`.
- [ ] Final runtime version set to `1.0.0` in `civora/__init__.py`.
- [ ] Changelog Unreleased section converted to `1.0.0` release entry.
- [ ] Exact release manifest created for final head.

## Security/operations gates

- [x] `.env` ignored by repository policy.
- [x] Release preflight rejects known CIVORA durable-state filenames in the release tree.
- [x] Direct durable-store editing forbidden by operator runbook.
- [x] Manual divergence remains fail-closed.
- [ ] Repository public/private posture explicitly accepted for release.
- [ ] Optional decision: pin GitHub Actions to immutable commit SHAs.
- [ ] Optional decision: add dedicated static/secret/security scanning gate.

## Governance gates

- [x] Canonical PR remains draft during technical closure.
- [ ] Production-readiness blockers R1-R3 validated as resolved by expanded CI.
- [ ] Release candidate declared technically ready.
- [ ] Final CI run passes on the exact proposed `1.0.0` head.
- [ ] Explicit human approval received for irreversible release operations.
- [ ] PR marked ready for review only after approval policy is satisfied.
- [ ] PR merged into `main`.
- [ ] `v1.0.0` tag/release created if release tagging is approved.

## Stop conditions

Release must stop if any of the following occurs:

- cross-platform CI failure;
- package build or installed-entrypoint smoke failure;
- release preflight failure;
- version metadata mismatch;
- unresolved corrupt/degraded durable-state invariant in release tests;
- release head changes after final validation without re-running CI;
- explicit release approval is absent.
