# CIVORA Checkpoint 0072 — Actionable Unified Health

Status: CLOSED_VALIDATED

## Objective

Expose canonical editorial remediation guidance directly through the primary consistency report and therefore through unified `civora health`, without duplicating recovery policy or adding a second mutation path.

## Implementation

`EditorialConsistencyInspector.inspect()` appends a `remediation` object generated by the existing `EditorialRemediationPlanner` after the consistency status, mismatches and recoverable mismatches are computed.

Because `UnifiedHealthInspector` already includes the complete consistency payload in the `editorial_consistency` component details, primary health output carries the same remediation classification automatically. The existing `civora editorial-consistency` command emits the same plan from the same source report.

No health-specific recovery rules were added. The planner remains the only remediation policy implementation and startup transaction replay remains the only automatic mutation path.

## Observable classifications

- `no_action` for consistent durable state;
- `automatic_recovery_available` only when every detected divergence is covered by an exact prepared editorial resolution transaction;
- `manual_investigation_required` for committed, ambiguous or otherwise unsupported divergence.

## Validation

`tests/test_health_remediation.py` covers:

- healthy unified health exposes `no_action`;
- a prepared crash window exposes `automatic_recovery_available` and the exact transaction identifier;
- committed divergence exposes `manual_investigation_required` and remains fail-closed;
- primary `civora health` JSON includes remediation guidance;
- `civora editorial-consistency` exposes the same canonical remediation plan and unhealthy exit behavior.

Cross-platform validation completed successfully in GitHub Actions run `31236264030` for canonical head `ed9506526bda9ed93587ef3faf850346c4520458`.

## Safety properties

- No duplicated remediation decision logic in health or CLI layers.
- No synthetic repair is introduced.
- No change to authoritative Approval Store semantics.
- No change to Review Queue state transitions.
- No change to transaction replay conditions.
- Manual divergence remains fail-closed.
- Operator output remains machine-readable and identifier-bound.
