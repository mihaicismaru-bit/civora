# CIVORA v2 — Development Charter

## Status

- Development line: `develop/civora-v2`
- Version: `2.0.0-dev.0`
- Frozen production baseline: `release/civora-v1`
- Baseline commit: `e2d83c280e98ce15f5e2a0c2ab47fb6719b0d423`
- Production domain remains: `valceaclar.ro`

## Non-negotiable rule

CIVORA v1 remains the rollback and regression reference. v2 development must not mutate the v1 snapshot and must not make production dependent on an unfinished v2 component.

## Development model

1. New structural and functional work targets `develop/civora-v2` or short-lived branches created from it.
2. Production `main` keeps the last validated behavior until a v2 promotion candidate passes the complete gate set.
3. v2 changes are additive or explicitly migratable. State/schema changes require a reversible migration path.
4. Multi-instance isolation is preserved: VÂLCEA CLAR remains the CIVORA `valcea` instance with its own state, media, metrics, corrections and credential namespaces.
5. Editorial discovery, verification and publication remain fail-closed. A v2 feature may improve ranking, speed, presentation or automation but may not weaken provenance or editorial gates.
6. Social publication remains channel-specific, idempotent and outbox-driven. Missing credentials, approval or adapters block only the affected channel.
7. Runtime state generated by production is authoritative over stale development copies. Development must never overwrite concurrent live state.
8. ChatGPT remains an operator/development console, not the production scheduler, state store or publishing runtime.

## v2 foundation priorities

- versioned contracts for stories, live feed, editions, venues, investigations and social outboxes;
- clean separation between discovery, evidence, editorial decision, rendering and distribution;
- migration-safe state handling and deterministic rollback;
- stronger observability, health checks and runtime reconciliation;
- feature flags or isolated activation paths for new presentation, commercial and viral-growth modules;
- mobile-first performance and resilient public rendering;
- regression tests against the frozen v1 baseline;
- preserved legal routes, canonical URLs, robots/sitemap behavior and source provenance.

## Promotion gate to production

A v2 release candidate is eligible for promotion only when all of the following are green:

- v1 regression/parity checks for functionality that must remain unchanged;
- editorial provenance and fail-closed validation;
- runtime/state migration and rollback validation;
- social deduplication/outbox validation;
- public HTTP/content checks for `valceaclar.ro`;
- legal/canonical/indexation checks;
- performance and mobile rendering checks;
- persistence reconciliation against the fresh production HEAD.

Until those gates pass, v1 remains the production reference and rollback target.
